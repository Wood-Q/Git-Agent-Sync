Git for your AI coding sessions

把 AI 编程会话，像代码一样带走。

Agent-Sync 是一个 Git 风格的会话同步工具。业务代码可以 clone 到另一台机器，但 Codex、Claude Code 的本地对话、命令上下文和项目路径通常不会跟过去。它把这些项目会话放进独立 sidecar Git 仓库，让你在任何机器上找回当时的工作现场。

Question

如果 AI 写代码的记忆，只存在这台电脑上？

Git 解决了源码迁移，却没有处理 agent 会话。一次调试里的推理、命令、报错、项目路径、上下文判断，往往留在本机的隐藏目录里。

01

换机器后，对话列表空了

业务仓库 clone 完整，但 Codex / Claude Code 的项目会话没有跟随仓库一起恢复。

02

回到旧 commit，却找不到当时的 agent 思路

代码能 checkout，讨论过程、命令尝试和上下文绑定却没有 Git 风格索引。

03

直接同步隐藏目录风险太大

账号、token、缓存、运行态、全局配置都不应该被粗暴打包进项目历史。

Inspired By Pain

它不是备份工具，而是在补上“AI 工作现场”的版本语义。

项目文档里反复强调一个边界：Agent-Sync 只把会话当作贴着 Git 项目走的本地资料，不污染业务仓库提交，也不把全局账号和缓存一起带走。

1现状

代码有远程仓库，会话只有本机路径

Codex 会话在 ~/.codex/sessions，Claude Code 会话在 ~/.claude/projects。这些文件里有上下文，但默认不会跟随业务仓库流动。

git clone your-project
cd your-project
# agent history: missing
2风险

会话里有价值，也有隐私

原始会话可能包含私有代码片段、终端输出、本地路径、prompt、调试信息，甚至密钥片段。因此它需要一个私有 sidecar 仓库，而不是混进业务 Git 历史。

.agent-sync-store/
└─ projects/<project-id>/
   ├─ codex/*.jsonl
   └─ claude/*.jsonl
3目标

让对话跟着项目，而不是跟着电脑

每次同步都记录业务仓库的 branch、HEAD commit、dirty 状态和同步说明。换机器后可以按 latest、current、branch、commit 或 bundle id 找回。

git agent-sync log --current
git agent-sync restore --latest 1
restored codex thread
How It Works

判断归属，靠结构化事实，不靠正文里提到项目名。

这是这个项目最关键的设计取舍：宁可少同步一些缺少元数据的老会话，也不因为聊天正文里出现项目名，就把别的项目会话混进来。

业务仓库

读取 Git root、remote、branch、HEAD commit 和 dirty 状态。

本机 agent 会话

扫描 Codex state / JSONL 和 Claude 项目 JSONL，只读取结构化 cwd、workdir、git 字段。

Sidecar Git Store

manifest.json 存最新快照，bindings.jsonl 存 append-only 历史索引。

私有远程仓库

sidecar 仓库独立 push / pull，不进入业务仓库提交历史。

另一台机器

按当前项目 identity 查找兼容 bundle，再恢复到本机 Codex / Claude 目录。
稳定项目身份

优先用规范化后的 Git remote 生成 projectIdentity 和 projectId，兼容 SSH / HTTPS 地址差异；没有 remote 时才退回目录名。

严格匹配规则

Codex 优先读 state_5.sqlite 的 threads 字段，再回退 JSONL；Claude 读顶层 cwd、Git 字段和 tool-use input。正文文本不是归属证明。

Git 上下文绑定

每次 push 都追加一条 binding：bundle id、agent 类型、业务 branch、HEAD commit、dirty 状态、会话标题和同步说明。

恢复时适配路径

跨系统恢复不会改 sidecar 原文件，只修改写回本机的副本：cwd、workdir、shell、transcript 中的项目根路径都会映射到当前机器。

Execution Flow

一条链路：业务仓库管代码，sidecar 仓库管会话。

CLI 设计成 Git 子命令的味道：init 建身份，status/scan 找会话，push 写快照，pull 拉 sidecar，log/show 浏览，restore 写回本机 agent 目录。

01

初始化项目身份

创建 .agent-sync/config.json 和独立的 .agent-sync-store/ Git 仓库，并把二者加入业务项目 .gitignore。

git agent-sync init --remote git@github.com:you/agent-session-store.git
02

扫描当前项目会话

优先用 Codex state 定位 rollout_path，跳过归档会话；再扫描 Claude 项目 JSONL。扫描缓存用 mtime、size、hash 减少重复 I/O。

git agent-sync status
git agent-sync scan --json
03

推送会话快照

匹配到的文件复制到 projects/<projectId>/，写入 manifest 和 binding，再只提交 sidecar 仓库。

git agent-sync push --m "feat: add login API"
04

另一台机器拉取索引

sidecar pull 支持 sparse checkout：只完整展开当前项目 bundle，其他项目只保留轻量 manifest 用于兼容匹配。

git agent-sync pull
git agent-sync log --latest
05

恢复可继续的对话

Codex 恢复会注册到 state_5.sqlite 和 session_index.jsonl；Claude 写入当前项目 slug 目录。

git agent-sync restore --current 1
git agent-sync restore --commit 4f7c2a1
Capabilities

它的价值在“可找回”，也在“不过界”。

Agent-Sync 的 MVP 能力已经覆盖 CLI、Codex、Claude Code、VS Code 扩展、pre-push hook、doctor 检查，以及按 Git 上下文恢复。

Git 风格命令

log 像浏览 Git 历史，show 查看单个快照，restore 把选中的会话写回本机。

双 agent 支持

支持 Codex 和 Claude Code，并针对两者不同的本机目录和元数据结构分别处理。

跨平台恢复

Windows、macOS、Linux 间恢复时，项目根路径和 shell 引用会映射到当前机器。

自动同步入口

install-hooks 可以安装 pre-push hook，在业务 Git push 前先同步 sidecar 会话。

会同步

Codex 项目 session JSONL Claude 项目 JSONL manifest.json bindings.jsonl branch / commit / dirty 会话标题与同步说明

默认不碰

账号与 token 全局 config / settings 缓存与遥测 运行态 session 插件和技能资产 业务仓库 Git 历史

首次同步

Takeaway

Agent-Sync 让 AI agent 的上下文，成为项目历史的旁路记忆。

它不替代 Git，也不污染 Git。它把会话、项目身份和 commit 绑定在一起，让你在另一台机器、另一个系统、另一个时间点继续同一段工程思路。
